# --- xfl.rs: the float_* raw call sites that live outside api/float.rs ---
#
# `float_set`/`float_multiply`/`float_mulratio`/`float_negate`/
# `float_compare`/`float_sum`/`float_invert`/`float_divide`/`float_one`/
# `float_mantissa`/`float_sign`/`float_int`/`float_log`/`float_root` are
# NOT called from `api/float.rs` — that module only wraps `float_sto`/
# `float_sto_set`/`slot_float` (see its own module doc comment). The other
# 14 `float_*` functions are called directly from `rshooks::xfl::XFL`'s
# inherent methods and operator trait impls (`Neg`/`Add`/`Mul`/`Div`), which
# is where the actual `rshooks_core::float_*` raw call sites live. Bridging
# only `api/float.rs` (as the family name might suggest) would leave these
# 14 functions permanently unreachable through the wrapper layer under
# `testenv` — so `xfl.rs` is scanned as an honorary member of the "float"
# bridged family, deviating from the literal `api/*.rs`-only file list in
# `.claude/design/TESTENV_PHASE2_DESIGN.md` §2/§7 for exactly this reason.
# `float_exponent` has no row here (and needs none): `XFL::exponent`
# decodes the exponent locally from the bit pattern — there is no
# `float_exponent` host call to bridge at all.

# --- xfl_unchecked.rs: XFLUnchecked's own raw float_* call sites (P2-E) ---
#
# `XFLUnchecked` (`crate::xfl_unchecked`) exists specifically to defer
# validation across a chain of hot-path XFL arithmetic (see its own module
# doc comment): `Neg`/`Add`/`Mul`/`Div` and `validate` each call
# `rshooks_core::float_*` directly, exactly like `xfl.rs`'s operators above
# (`Sub` is the one exception — implemented as `self + (-rhs)`, dispatching
# to this same file's own `Add`/`Neg` impls, so it has no raw call site of
# its own, matching `xfl.rs::sub`'s identical absence from the list above).
# `TESTENV_PHASE2_DESIGN.md` §4's original file list only mentions
# `api/*.rs`/`xfl.rs`; this file is scanned as a second honorary member of
# the "float" bridged family for the same reason `xfl.rs` is (deviating from
# the literal file list), discovered when P2-D found `examples/07`'s real
# accept path structurally unreachable because these sites were unbridged —
# a hook using `XFLUnchecked` silently fell back to the raw
# `NOT_IMPLEMENTED` host stub under `testenv` even with a backend installed.

xfl_unchecked.rs::add -> float_sum
xfl_unchecked.rs::div -> float_divide
xfl_unchecked.rs::mul -> float_multiply
xfl_unchecked.rs::neg -> float_negate
xfl_unchecked.rs::validate -> float_sum
